# Issue Tracker

This repo uses GitHub Issues as the intended source of truth for work items, PRDs, triage tickets, and implementation tasks.

## Workflow

- Use `gh issue list`, `gh issue view`, and `gh issue create` when issue operations are needed.
- Link implementation work back to the relevant GitHub issue whenever possible.
- If the repo has not yet been connected to a GitHub remote, treat GitHub Issues as the intended tracker and record local notes only as temporary scratch material.

## Expected issue types

- Product discovery notes
- PRDs
- Implementation slices
- Bug reports
- Review or triage follow-ups
